# VPS y Coolify
1. Usar una instalación por cliente: prefijo de volúmenes, proyecto Compose y dominio únicos. El aislamiento de equipos de Kimai requiere configurar permisos; no sustituye instalaciones separadas para clientes independientes.
2. Ejecutar el inicio privado del README. Esperar que `docker compose ps` muestre base saludable; revisar `docker compose logs --tail 100 app`. La imagen ejecuta instalación/migraciones al arrancar. ADMINMAIL/ADMINPASS crean admin solo si no existe; no cambian su clave después.
3. En la sesión privada cambiar la clave del administrador, habilitar 2FA si corresponde y crear cuentas individuales con permisos mínimos. Configurar idioma, zona horaria y clientes antes de cargar horas reales.
4. Quitar la publicación local y las variables de alta inicial recreando app con `docker compose -f compose.yaml up -d --force-recreate app`. Revisar que no aparezca un puerto host 8001. Guardar y luego quitar ADMINPASS del `.env` cuando termine el alta; el Compose de producción no lo necesita.
5. Para Coolify cargar este directorio como recurso Docker Compose. Copiar las variables del `.env` al entorno del recurso y conservar los nombres explícitos VOLUME_PREFIX del mismo VPS si se reutilizan datos. No ejecutar dos apps sobre los mismos volúmenes. Detener el recurso anterior antes del cambio. Usar el contexto Compose del recurso para los scripts; un proyecto distinto puede crear una base vacía.
6. Asociar dominio HTTPS al servicio app, puerto interno 8001. Configurar TRUSTED_PROXIES con la IP/CIDR concreta de la red del proxy de Coolify (inspeccionar red del contenedor); no confiar en todo Internet. Mantener TRUSTED_HOSTS con el dominio real y localhost para el healthcheck. Verificar esquema HTTPS, cookies y redirecciones sin bucles antes de publicar.
7. No exponer MariaDB ni publicar puertos adicionales. Configurar SMTP en MAILER_URL según Kimai, codificando caracteres especiales de credenciales URL. Guardarlo como secreto; hacer prueba de envío/recuperación con una cuenta de ensayo.
8. Ejecutar docs/aceptacion.md. A continuación configurar respaldo externo y monitor HTTP de la página de acceso.

La etiqueta MariaDB 11.4 recibe actualizaciones de su rama. Registrar el digest desplegado antes de cada actualización. Kimai está fijado por versión y digest. Actualizar deliberadamente después de respaldo y prueba en un clon; no automatizar saltos de versión mayor.
